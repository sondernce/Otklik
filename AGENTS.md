# Работа над «Откликом»

Перед изменениями прочитай `development-plan.md`: это текущий план и список согласованных решений. После завершённого этапа обновляй раздел о ходе работы и отмечай следующий шаг.

Дорабатываем существующее приложение в `otklik/`. Используем Python со стандартной библиотекой, SQLite, HTML, CSS и обычный JavaScript. Не переписывай проект и не переводи его на Django без нового указания пользователя.

Исторические описания и макеты не заменяют решения из плана. Демонстрационные цифры, отзывы и функции из макетов не считаются утверждёнными требованиями.

Проверки выполняй на временной базе через `OTKLIK_DB`. Не используй `.local/otklik.sqlite3` для тестовых аккаунтов. Изменения схемы оформляй миграциями с резервной копией существующих данных.

Текущее оформление сохраняем. Не меняй цвета, композицию и внешний вид существующих страниц без нового указания пользователя. Переписка по записи, поддержка, уведомления, сессии всех ролей в SQLite, средства копирования и локальная диагностика реализованы. По решению пользователя шаги с внешними подключениями и решениями отложены. 18 ноября реализован утверждённый административный обзор и журналы. Следующий продуктовый этап требует согласования почты, видеосвязи и условий пилота. Внешние подключения остаются отложенными. Не подключай внешние сервисы и не публикуй локальный сервер без нового указания. Актуальное состояние сверяй с планом.

Для журнала используй `diagnostics.record()` с фиксированными событиями. Не записывай тексты исключений, запросы, cookie, токены и переписку; не возвращай стандартный traceback в обработку ошибок сервера. Настройки и ограничения описаны в `docs/local-diagnostics.md`.

Текущие сценарии проверены без расширения функций. Поздние ответы браузера должны проверяться относительно текущего входа, данные кабинета очищаются при выходе. Повтор исходного запроса записи остаётся идемпотентным после переносов. Подробности и проверки: `docs/workflow-review.md`.

Запросы интерфейса направляй через `HttpAPI.request()` из `static/js/http.js`. Общий предел ожидания составляет 15 секунд, включая чтение тела ответа. Не добавляй автоматический повтор POST: сервер мог сохранить изменения до потери ответа. При сетевой ошибке сохраняй форму и ключ запроса. Правила повтора описаны в `docs/network-behavior.md`.

Восстановление через `otklik/backup.py` создаёт только новый файл и завершает прежние сессии в нём. Не заменяй рабочую базу при проверках. Расписание автоматических копий не настроено; оно относится к подготовке размещения. Команды описаны в `docs/backup-and-restore.md`.

Добавляй проверки надёжности вместе с функциями: права доступа, повторные и одновременные запросы, ошибки сети, откат операций и сохранность базы. Обнаруженную ошибку сначала воспроизведи тестом, затем исправь. Браузерные сценарии сохраняй в проекте для повторного запуска.

Для пользовательских текстов применяй `/home/pup/.agents/skills/humanizer/SKILL.md`. Пиши по-русски, сохраняй технические идентификаторы.

Административный обзор и журналы описаны в `docs/admin-monitoring.md`. Схема 7 сохраняет события операций в той же транзакции; не логируй тексты анкеты, сообщения или комментарии решений. События ошибок и безопасности читаются только из ограниченного журнала, с повторной фильтрацией полей. Даты копий хранятся отдельно от рабочей SQLite; автоматическое расписание не настроено. Новые API доступны только администратору.
