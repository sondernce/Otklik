# Проверки «Отклика»

Команды ниже выполняются из папки `otklik/`. Все серверные и браузерные проверки используют временные базы. Рабочая `.local/otklik.sqlite3` не используется.

## Сервер и клиентские функции

```sh
python3 -B -m unittest discover -s tests -v
node tests/test_client_times.cjs
```

Серверные проверки охватывают доступ к данным, регистрацию и сессии, рассмотрение анкет, бронирование, отмену, перенос и миграции. Проверки надёжности добавляют:

- ошибочные HTTP-запросы без изменения данных;
- истёкшую сессию и восстановление доступа после входа;
- одновременную отмену встречи и принятие переноса;
- блокировку SQLite с безопасным повтором запроса;
- исключение после части изменений и полный откат транзакции;
- восстановление базы из копии с сохранением сессии и предложения переноса;
- сбой миграции, сохранение прежней схемы и успешный повтор.

`test_client_times.cjs` проверяет минуты, передачу выбранной даты и времени, сохранение ответов и границы временных фильтров.

## Браузерные проверки

Для браузерных проверок нужны Node.js 20+ и Playwright. Зависимости тестов находятся в `tests/package.json`; они не требуются для запуска сайта.

Однократная подготовка:

```sh
npm --prefix tests install
npm --prefix tests run install-browser
```

Запуск:

```sh
python3 -B tests/run_browser.py
```

Запускатель сам создаёт временную базу, поднимает сервер на свободном локальном порту и завершает его после проверок. Не нужно запускать основной сервер или задавать `OTKLIK_DB`. При необходимости путь к установленному браузеру можно передать через `BROWSER_EXECUTABLE_PATH`.

В `browser.test.cjs` сохранены четырнадцать сценариев:

1. Подбор, регистрация, запись, подтверждение, обновление страницы и мобильное отображение.
2. Перенос и отмена обеими сторонами, повторная запись и сохранение одобренной анкеты.
3. Обрыв сети до получения сервером заявки: выбор сохраняется, повтор работает.
4. Потеря ответа после сохранения заявки: повтор не создаёт вторую встречу.
5. Истечение входа во время записи: после повторного входа выбранное время сохраняется.
6. Отображение недоверенного текста профиля без выполнения HTML.
7. Переписка участников, обновление без потери черновика и очистка при выходе.
8. Отдельные обращения клиента и психолога, ответ администратора, закрытие и повторное открытие.
9. Обрыв сети до отправки сообщения: текст остаётся в форме, повтор работает.
10. Потеря ответа после сохранения сообщения: повтор не создаёт дубль.
11. Уведомления клиента открывают переписку, обновляют счётчики и сохраняют прочитанность после перезагрузки; мобильное отображение и очистка при выходе.
12. Уведомления психолога и администратора открывают нужную встречу или обращение, в том числе из другого раздела кабинета.
13. Поздний ответ сервера с уведомлениями не возвращает личные данные в интерфейс после выхода.
14. Повтор выхода после потери ответа сервера завершает вход и очищает личные данные в интерфейсе.

Набор создаёт несколько аккаунтов за короткое время. Если срабатывает ограничение регистрации или входа, подготовка теста ожидает его снятия, не отключая защиту сервера. Полный запуск может занять больше минуты.

`test_communications.py` проверяет доступ участников, приватность поддержки, повторную и одновременную отправку, проверку текста, постраничное чтение, ограничение частоты, закрытие обращений, откат операций, восстановление копии и миграцию сообщений. При необходимости мобильные снимки можно сохранить, задав папку в `OTKLIK_TEST_ARTIFACTS`.

`test_notifications.py` проверяет получателей уведомлений, отсутствие текста переписки, все исходы переноса, истечение заявки, защиту от дублей, прочитанность, границу массовой отметки и постраничное чтение при поступлении новых событий. Проверяются откат сообщения при ошибке сохранения уведомления, миграция с версии 3, резервная копия и повтор миграции после сбоя.

Сценарии проверяют отсутствие необработанных ошибок JavaScript. Сейчас браузерные проверки выполняются в Chromium. Остальные браузеры, нагрузка и принудительное завершение процесса во время записи пока не проверяются. Процент покрытия кода не измерен.

## Проверки объединённой версии

`test_integration.py` проверяет настройки клиента, изоляцию пользователей, приватность и HTTPS-валидацию видеоссылок, конфликт устаревшей формы и доступность ресурсов после перемещения в `templates/` и `static/`. Зафиксированы 63 успешных серверных теста и 13 браузерных сценариев. При установке браузерных зависимостей используйте `npm ci` из `tests/`, чтобы следовать `package-lock.json`.

## Сессии и резервные копии

`test_access.py` проверяет сессии и ограничения входа из другого процесса, хеши токенов, срок действия, отзыв и повтор выхода, замену текущей сессии и сохранение доступа другого устройства. Есть проверки ролей, Host и Origin, независимых ограничений аккаунтов, одновременных попыток, миграции версии 5 и отката регистрации при ошибке записи сессии.

`test_backup.py` проверяет команды создания, проверки и восстановления, сохранность диалогов и встреч, завершение сессий после восстановления, обновление схемы, работу с WAL, отказ от существующего пути, повреждённых данных и очистку временных файлов. Все копии создаются из временных тестовых баз.

После этих доработок прошли 82 серверных теста и клиентская проверка времени. Все 13 прежних браузерных сценариев прошли; новый сценарий повтора выхода проверен отдельно. Всего в браузерном наборе 14 сценариев.
