# Регистрация после подтверждения почты

28 ноября 2026 года. Действует для новых клиентов и психологов. Старые аккаунты не удаляются и продолжают входить обычным способом.

## Путь пользователя

1. Пользователь заполняет форму и нажимает кнопку регистрации.
2. Открывается `/registration#role=client` или `/registration#role=psychologist`. Доступ в кабинет ещё отсутствует.
3. Вводит шестизначный код из письма и нажимает «Подтвердить и создать аккаунт».
4. Сервер одной транзакцией создаёт пользователя, подтверждённый адрес, сессию и, для психолога, черновик анкеты. Клиент возвращается к выбранному времени, если оно сохранено; подтверждение регистрации само по себе не бронирует слот.

Ошибки показываются около поля. Обновление страницы сохраняет шаг через HttpOnly-cookie. Почту можно исправить до создания аккаунта; новый код приходит уже на исправленный адрес. Старый код после замены не подходит. Пароль после формы очищается и не попадает в браузерное хранилище. Временная заявка содержит только соль, хеш пароля и данные формы; она не отображается в списках аккаунтов и метриках регистраций.

## Ограничения и повторы

Код действует 10 минут, не более пяти проверок неверного кода. Повторная отправка доступна через 60 секунд; действуют ограничения почтовых запросов по адресу и подключению. Исправление другого адреса доступно сразу с ограничением частоты. Секрет cookie различается для клиента и психолога; в базе хранится его хеш. Код в базе хранится хешем с привязкой к заявке. В очереди письмо до обработки содержит код и требует закрытого доступа, как прежние почтовые ссылки.

Стабильный `request_key` формы позволяет повторить потерянный ответ начала регистрации без второго письма; изменённые данные с тем же ключом отклоняются. Автоматического повтора POST нет. После завершённого подтверждения повтор не создаёт ещё одного пользователя и не выдаёт новую сессию. Если успешный ответ потерян, можно войти с указанным при регистрации паролем. Параллельные подтверждения защищены `BEGIN IMMEDIATE` и проверкой завершённой заявки. Занятость адреса проверяется повторно внутри транзакции.

Временные заявки действуют 24 часа. Истёкшие удаляются при последующих запросах регистрации, их очередь очищается; отдельный фоновый сборщик пока не запущен. При успешной регистрации хеш пароля, соль, данные формы и код в заявке очищаются сразу, остаток заявки нужен до 10 минут для обнаружения повторного подтверждения. Старые локальные `.eml` автоматически не удаляются.

## Почта сейчас

Внешний отправитель не подключён. В режиме `local` письмо стоит в закрытой очереди; обработчик `mail_worker.py` формирует `.eml`. В нём есть строка «Код подтверждения: …». Экран явно сообщает, что доставка в ящик ещё не подключена. Для тестирования используются отдельные временные базы. В режиме SMTP используются существующие настройки защищённой отправки; сам обработчик регистрации SMTP не запускает.

## API и база

`POST /api/{role}/register` теперь возвращает `verification_required`, адрес и сроки, устанавливает только cookie незавершённой регистрации. Пользователя и авторизованной сессии ещё нет.

- `GET /api/{role}/registration/status` — восстановить шаг для текущей cookie, без кода, пароля и токенов.
- `POST /api/{role}/registration/confirm` с `code` — проверить код и создать аккаунт.
- `POST /api/{role}/registration/resend` — заменить код.
- `POST /api/{role}/registration/change-email` с `email` — исправить адрес и заменить код.

Роль принимает только `client` и `psychologist`. Схема 11 добавляет `pending_registrations` с резервной копией перед миграцией. Восстановление отменяет письма незавершённых регистраций и удаляет временные заявки, не создавая пользователей. Методы подтверждения по ссылкам сохранены для старых неподтверждённых аккаунтов и восстановления пароля.

## Проверки

Тесты регистрации проверяют отсутствие аккаунта до кода, обе роли, закрытый статус, неправильные и истёкшие коды, ограничение попыток, повтор регистрации, исправление адреса, конкурирующие подтверждения, откат при ошибке сессии, очистку, миграцию 10 → 11 и восстановление. Браузер проверяет путь записи клиента, сохранение черновика, мобильный экран психолога, исправление почты и обновление страницы. Полный прогон старых браузерных сценариев сохранён; независимые тестовые контексты имитируют разных посетителей только в отдельном сервере `tests/run_browser.py`, реальные ограничения производственного сервера не меняются.
