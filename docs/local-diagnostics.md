# Запуск и диагностика

Команда запуска из `otklik/` остаётся прежней:

```sh
python3 -B server.py
```

Сервер доступен только по `127.0.0.1`. Порт по умолчанию: `4173`. Публичный режим, почта и внешнее наблюдение за сбоями не подключаются этой доработкой.

## Настройки

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `OTKLIK_PORT` | Целое число от 1 до 65535 | `4173` |
| `OTKLIK_DB` | Файл SQLite | `.local/otklik.sqlite3` рядом с сервером |
| `OTKLIK_LOG_DIR` | Папка журнала | `logs` рядом с выбранной базой |

При стандартном запуске журнал находится в `otklik/.local/logs/otklik.log`. Каждая запись JSON занимает одну строку. Записи содержат время UTC, тип события и безопасные сведения об ошибке. Для исключения сохраняются его тип и до восьми кадров стека с именами файлов приложения и номерами строк. При наличии сохраняется числовой код SQLite.

Полные пути, строки исходного кода, локальные переменные и текст исключения в записи не включаются. Журнал не получает тело запроса, адрес с параметрами, cookie, пароли, токены, сообщения или данные анкеты. Обычные HTTP-запросы не записываются. Имена событий и набор полей ограничены в `diagnostics.py`.

## Размер и доступ

Журнал ограничен примерно 1 МБ на файл. После заполнения он переносится в `otklik.log.1`, предыдущий файл в `otklik.log.2`. Более старые записи удаляются. На Linux файлы создаются с правами `0600`; текущий файл также получает эти права при запуске. Журналы исключены из Git и не выдаются через сайт.

Если журнал нельзя открыть при запуске, сервер не начинает работу. Если запись перестала работать позже, например из-за заполненного диска, приложение не выводит исходное исключение: в терминале появляется одно сообщение о проблеме журнала. После устранения причины перезапустите сервис.

## Ошибки запуска

- Неверный `OTKLIK_PORT`: исправьте число. Введённое значение не повторяется в сообщении об ошибке.
- Занятый порт: остановите другой экземпляр или выберите другой `OTKLIK_PORT`. Проверка происходит до открытия и миграции базы.
- Недоступный путь: проверьте `OTKLIK_DB` и права на папку. При недоступном журнале отдельно проверяется `OTKLIK_LOG_DIR`.
- Более новая версия базы: используйте совместимую версию приложения или проверенную копию. Такая база не мигрируется и не изменяется.
- Повреждение или блокировка SQLite: проверьте файл и его целостность, освободите блокировку. Команды проверки и восстановления описаны в [инструкции по копиям](backup-and-restore.md).

Ошибка запуска возвращает ненулевой код завершения и короткое сообщение без traceback. Сообщение с адресом сервера появляется только после успешного открытия порта и базы. Остановка через Ctrl+C закрывает сервер и записывает событие остановки.

## Ошибки во время работы

Неожиданные исключения при GET и POST дают общий ответ HTTP 500. Ошибки базы или файлов дают HTTP 503. В JSON-ответе есть `request_id`, по нему можно найти запись в журнале. Это случайный идентификатор запроса, он не содержит идентификатора аккаунта или встречи. Пользовательские ошибки проверки полей продолжают возвращаться в прежнем формате.

Ошибки вне обработчиков запросов также записываются через безопасный обработчик сервера, без стандартного вывода traceback с текстом исключения.

## Проверки

`tests/test_diagnostics.py` проверяет неправильный и занятый порт, повреждённую и более новую базу, недоступные пути, совпадение пути журнала с базой, успешный запуск и Ctrl+C. Проверяются отсутствие личных данных в журнале, связь `request_id` с ответом, ротация, права файлов и ошибка записи журнала. Проверки используют временные базы и папки.
