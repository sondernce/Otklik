# Почта: очередь и локальная проверка

Домен и почтовый сервис ещё не выбраны. Работают очередь в SQLite, обработчик локальных писем и SMTP, подтверждение адреса и восстановление пароля клиента и психолога. Новые регистрации с 28 ноября сначала создают временную заявку и письмо с шестизначным кодом. Пользователь и сессия появляются только после подтверждения кода; подробности в `registration.md`. Письма о встречах и напоминания пока не подключены. Подтверждение почты не блокирует запись, редактирование анкеты или доступ к существующим встречам: ограничения до подтверждения адреса ещё не согласованы.

## Локальный режим

Команды выполняются из `otklik/`, путь должен указывать на отдельную тестовую базу:

```sh
python3 -B mail_worker.py --database /path/to/test.sqlite3 --status
python3 -B mail_worker.py --database /path/to/test.sqlite3
```

Обработчик выполняет один проход, до 20 писем; лимит можно изменить через `--limit` от 1 до 100. В режиме по умолчанию выбираются только задания с `transport='local'`. Письма сохраняются в `mail-preview/` рядом с выбранной базой. Это файлы `.eml`, которые можно открыть почтовой программой или текстовым редактором. Реальная отправка в этом режиме отсутствует. Если очередь пустая, письма не создаются.

Имена файлов определяются идентификатором задания. Файлы публикуются атомарно с правами `0600`, папка создаётся с `0700`. Повтор после остановки процесса не создаёт второй файл и не перезаписывает другой файл с тем же именем. Папка исключена из Git и не выдаётся HTTP-сервером. Файлы могут содержать адреса и секретные ссылки; для разработки используйте тестовые данные, удаляйте ненужные `.eml` вручную. Автоматическая очистка локальных файлов пока не добавлена.

После успешного формирования локального письма очередь имеет статус `preview`; это не отправка адресату. Тело, тема и получатель в строке очереди очищаются. Сам `.eml` остаётся для проверки.

## Подключение SMTP позже

Шаблон настроек находится в `.env.example` в корне проекта. Приложение не загружает `.env` автоматически: значения должны передаваться через окружение процесса. Настоящие пароли и ключи не помещать в Git и не присылать в чат.

| Переменная | Назначение |
| --- | --- |
| `OTKLIK_MAIL_TRANSPORT` | Режим новых писем: `local` по умолчанию или `smtp` |
| `OTKLIK_PUBLIC_URL` | HTTPS-адрес сайта без пути, нужен при `smtp` для ссылок |
| `OTKLIK_MAIL_FROM` | Один адрес отправителя без отображаемого имени |
| `OTKLIK_SMTP_HOST` | SMTP-сервер выбранного сервиса |
| `OTKLIK_SMTP_PORT` | Порт, по умолчанию 465 для SSL или 587 для STARTTLS |
| `OTKLIK_SMTP_SECURITY` | `ssl` или `starttls`; незашифрованный режим отсутствует |
| `OTKLIK_SMTP_USER` | Пользователь SMTP |
| `OTKLIK_SMTP_PASSWORD` | Пароль приложения или SMTP-пароль |

После настройки отправителя SMTP включается явной командой:

```sh
python3 -B mail_worker.py --database /path/to/database.sqlite3 --mode smtp
```

Команда выбирает только задания `transport='smtp'`. Переключение режима не отправляет локальные тестовые задания. Проверка настроек выполняется до захвата задания; при неполных настройках очередь остаётся нетронутой. TLS проверяет сертификат сервера, на сетевые операции установлен таймаут 15 секунд. Обработчик не запускается автоматически при открытии сайта. Расписание запуска пока не настроено.

## Состояния и повторы

`mail_queue.enqueue()` вызывается внутри транзакции бизнес-операции. Уникальный ключ события и отпечаток содержимого предотвращают повторную постановку одинакового письма. Изменённое письмо с прежним ключом отклоняется. Добавление в очередь не отправляет письмо и не фиксирует транзакцию за вызывающий код.

| Статус | Значение |
| --- | --- |
| `pending` | Ожидает обработки или безопасной повторной попытки |
| `sending` | Задание захвачено обработчиком на срок до 120 секунд |
| `sent` | SMTP-сервер подтвердил приём; доставка в ящик адресата не проверена |
| `preview` | Файл письма сформирован локально |
| `failed` | Окончательный отказ или исчерпаны безопасные повторы |
| `unknown` | Результат SMTP неизвестен, автоматический повтор запрещён |
| `cancelled` | Срок истёк либо задание отменено при восстановлении базы |

Одновременные обработчики захватывают задания транзакцией `BEGIN IMMEDIATE`. Захват имеет случайный идентификатор, чужой или просроченный обработчик не может перезаписать результат. SMTP выполняется после завершения транзакции захвата, без удержания блокировки базы на время сети.

Сбой соединения до передачи письма и явный временный отказ SMTP допускают повтор с задержкой от минуты, максимум шесть попыток. Потеря ответа во время передачи DATA считается неизвестным исходом. Задание не отправляется автоматически снова, даже если письмо могло не дойти. Остановка SMTP-обработчика с истёкшим захватом также переводит задание в `unknown`. Стабильный Message-ID не считается гарантией отсутствия дублей у получателя.

По умолчанию срок жизни задания семь дней; подтверждение и восстановление задают собственный срок; напоминания при подключении тоже должны задавать срок. Истёкшие ожидающие задания отменяются при обработке очереди, содержимое очищается. После успешного приёма SMTP, формирования локального файла или окончательного отказа получатель, тема и тело в строке очереди тоже очищаются. До обработки очередь содержит письмо, поэтому база и копии требуют закрытого доступа. Журнал не получает содержимое писем или текст исключений SMTP.

## Администратор и резервные копии

Обзор администратора показывает количества по статусам. Сводка не раскрывает адреса, тему, тело, ключ события и секретные ссылки. Через `--status` доступна безопасная сводка и последние 20 служебных состояний.

Миграция версии 7 в 8 создаёт `mail_outbox` и индекс. Перед обновлением существующей базы сохраняется копия. При пробном восстановлении базы незавершённые почтовые задания отменяются, содержимое очереди очищается. Исходная рабочая база остаётся прежней. Это исключает автоматическую отправку старых писем из восстановленной копии.

## Подтверждение адреса существующих аккаунтов и восстановление пароля

В обоих кабинетах есть ссылка «Забыли пароль?». В настройках отображаются подтверждение адреса, кнопки запроса письма и обновления статуса. При регистрации первое письмо с кодом создаётся автоматически (см. `registration.md`), а локальный обработчик нужно запускать отдельно: регистрация не открывает SMTP и не формирует `.eml` внутри HTTP-запроса.

Пример локальной проверки после регистрации и при работающем сервере, из `otklik/`:

```sh
python3 -B mail_worker.py
```

Команда обработает локальные задания выбранной по `OTKLIK_DB` базы; без переменной используется `.local/otklik.sqlite3` рядом с сервером. Откройте нужный файл в `.local/mail-preview/` и скопируйте ссылку в браузер. Для тестов используйте отдельную базу. Файлы содержат секретные ссылки, их нельзя публиковать или добавлять в репозиторий.

Подтверждение действует 24 часа. После перехода нужно явно нажать «Подтвердить почту». Обычное открытие ссылки или GET-запрос не меняют состояние. Запрос сброса возвращает одинаковый ответ для существующей и неизвестной почты. Ссылка сброса действует 30 минут, форма требует дважды ввести новый пароль. Успешная смена завершает все сессии только соответствующего аккаунта; другие пользователи и роли сохраняют доступ. Доступ к письму также подтверждает адрес.

Ссылки одноразовые, привязаны к роли, аккаунту, адресу и назначению. Старые ссылки отзываются при выдаче новой для того же назначения. Успешное подтверждение или смена пароля отзывает остальные неиспользованные ссылки аккаунта. Одновременные запросы не могут использовать один токен дважды. При потере ответа повторный сброс не меняет пароль снова: страница предлагает войти с уже установленным паролем.

Секрет передаётся после `#`, поэтому не попадает в URL HTTP-запроса. Страница `/account-access` извлекает его в память и очищает видимый адрес; секрет не сохраняется в `localStorage` или `sessionStorage`. Нажатие кнопки отправляет JSON через существующий транспорт с таймаутом 15 секунд. Обновление страницы потребует снова открыть исходную ссылку из письма. Переход на новую ссылку в той же вкладке обновляет форму, поздний ответ предыдущей ссылки игнорируется.

В таблице `email_tokens` хранятся только хеши токенов. Само письмо до обработки содержит ссылку в закрытой очереди, а после локальной обработки ссылка остаётся в приватном `.eml`. Почтовый транспорт по-прежнему очищает тему, тело и получателя в обработанной строке очереди. Журналы и административные API секретные ссылки не получают.

Локальная ссылка сохраняет разрешённый исходный адрес, `localhost` или `127.0.0.1`, и порт, чтобы браузер сохранил сессию и выбранную встречу. Произвольный `Host` не используется. Для SMTP нужен явно заданный `OTKLIK_PUBLIC_URL` с HTTPS; это не включает публичное размещение локального сервера.

Повторная выдача ограничена одной минутой между запросами и тремя запросами на адрес, роль и назначение за 15 минут; превышение не раскрывает наличие аккаунта. Суммарный предел запросов писем с адреса подключения составляет 30 за час. Первая регистрация защищается отдельными существующими ограничениями регистрации. IP и почта в таблицу ограничений попадают только в виде хешей. Проверка токенов имеет отдельные лимиты, независимые для разных секретов.

Схема 9 добавляет `email_status`, `email_tokens` и `email_requests` с резервной копией перед миграцией. Старым аккаунтам не назначается подтверждённый адрес автоматически. При восстановлении копии все неиспользованные ссылки отзываются; незавершённые письма отменяются. Созданные пользователи, встречи, переписка и прежняя рабочая база сохраняются.

Адрес администратора сейчас отсутствует. Его восстановление на почту не переносилось, ссылки доступны только для клиентов и психологов. Смена адреса с подтверждением нового ящика реализована в схеме 10. [Правила аккаунтов](accounts-and-outcomes.md).

## Следующий шаг

Подключить организационные письма о встречах и напоминания. Выбрать домен и отправителя для проверки реальной доставки, настроить расписание обработчика. До пилота отдельно согласовать ограничения действий до подтверждения адреса. Оплата, видеосервис и публичное размещение этим этапом не включаются.
