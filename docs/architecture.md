## Ответственность модулей

| Модуль | Ответственность |
| --- | --- |
| `server.py` | Точка входа, HTTP, аутентификация, определение роли и вызов операций |
| `database.py` | Соединения SQLite, версии схемы, миграции и копия перед миграцией |
| `access.py` | Хеши токенов сессий всех ролей, отзыв и ограничения попыток входа |
| `admin_monitor.py` | Обзор администратора, фильтры и транзакционный журнал операций |
| `maintenance.py` | Служебные даты успешных копий и проверок восстановления вне рабочей базы |
| `diagnostics.py` | Журнал с ограниченным набором полей, ротация и исключение личных данных |
| `backup.py` | Копирование работающей SQLite, проверка и восстановление в новый файл |
| `booking.py` | Доступность, запись, отмена и согласование переноса |
| `publications.py` | Последняя одобренная версия анкеты и публичные поля |
| `client_profiles.py` | Проверка и сохранение настроек клиента |
| `video_links.py` | Проверка HTTPS-ссылки, прав психолога и версии встречи |
| `communications.py` | Личные сообщения и отдельная поддержка |
| `notifications.py` | Триггеры уведомлений, выборка и прочитанность |
| `timestamps.py` | UTC и разбор времени с часовым поясом |
| `web_assets.py` | Явный список доступных страниц и ресурсов |

Модули операций принимают соединение SQLite и идентификатор пользователя, а не HTTP-запрос. Обработчик сервера открывает соединение через контекстный менеджер: успешная операция фиксируется, исключение откатывает транзакцию, соединение закрывается. Операции, требующие сериализации записи, начинают `BEGIN IMMEDIATE`.

База и миграции не зависят от HTTP-сервера. Существующие вызовы `booking.connect`, `booking.publish` и `booking.publication` сохранены через импорты для совместимости. Новые обращения к инфраструктуре можно направлять прямо в соответствующий модуль.

## Интерфейс

Страницы используют абсолютные ссылки `/static/css/...` и `/static/js/...`. Адреса `/`, `/client`, `/psychologist`, `/admin` сохранены. Старые адреса отдельных JS/CSS оставлены как совместимые маршруты. Исходники Python, `templates/` и пользовательская база по HTTP не выдаются.

`dashboard.css` содержит общую оболочку кабинетов и базовые стили календарей. `client.css` содержит клиентский кабинет и месячный календарь; `psychologist.css` — дополнительные стили записей психолога. Клиентская страница больше не подключает CSS с названием кабинета психолога. `booking-ui.js` и `communications-ui.js` остаются общими компонентами браузера. Все запросы интерфейса используют `http.js`: предел ожидания 15 секунд включает чтение JSON, автоматических повторов POST нет. [Поведение при сетевых ошибках](network-behavior.md).

## Данные и запуск

Стек сохранён: стандартная библиотека Python 3.12+, SQLite, HTML/CSS/JavaScript без сборки. Запуск из `otklik/`: `python server.py`. Пути `OTKLIK_DB` и `OTKLIK_PORT` работают как прежде. Текущая схема: версия 10. Версия 5 добавила возраст и ссылки на встречи; версия 6 добавляет сессии психолога и администратора и учёт попыток входа. Версия 7 добавляет учёт регистраций и транзакционный журнал операций.

Тесты создают временные базы. Пользовательские базы разных копий не объединяются автоматически. Сессии всех ролей и попытки входа хранятся в SQLite. В базе находятся хеши токенов, срок действия составляет восемь часов. Восстановление через `backup.py` завершает все сессии только в новой базе. Команды описаны в [инструкции](backup-and-restore.md).

`server.main()` проверяет настройки и открывает порт до подключения к базе. Неподдерживаемая более новая схема отклоняется в `database.connect()` без изменения файла. Журнал настраивается через `OTKLIK_LOG_DIR`, по умолчанию находится в папке `logs` рядом с выбранной базой. Полные тексты исключений и запросов в него не передаются. Ошибки GET, POST и потока сервера обрабатываются через `diagnostics.record()`. [Подробности диагностики](local-diagnostics.md).

В кабинете администратора используются `admin-monitor.js`, приватные `/api/admin/overview` и `/api/admin/events`. Обзор обновляется раз в 30 секунд в видимой вкладке. Чтение использует транзакцию для согласованного снимка счётчиков; просмотр не меняет статусы заявок. [Состав мониторинга](admin-monitoring.md).

`mail_queue.py` отвечает за транзакционную почтовую очередь, `mail_worker.py` за отдельную обработку локальных писем или SMTP. Схема 8 добавляет `mail_outbox`; восстановление отменяет незавершённые задания. [Текущие возможности и ограничения](email.md).

`email_access.py` выдаёт и использует одноразовые ссылки, хранит подтверждение адреса и ограничения запросов. Схема 9 добавляет соответствующие таблицы. Пароль хешируется общим `access.password_hash()`, сброс отзывает сессии только нужного аккаунта. Страница `/account-access` получает секрет через фрагмент, очищает URL и выполняет изменения только по явному POST. Существующее оформление сохранено. [Проверка локальных писем](email.md).

`accounts.py` отвечает за состояния аккаунтов, подтверждённую смену почты и удаление личных полей профиля. `outcomes.py` хранит ответы участников о встрече и решение администратора отдельно от бронирования. Схема 10 добавляет эти данные; старым встречам результат не назначается. [Правила и ограничения](accounts-and-outcomes.md).
